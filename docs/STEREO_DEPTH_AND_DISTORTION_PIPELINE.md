# EGO 双目深度、鱼眼校正与 MANO 实时流程

本文说明当前项目究竟是单目还是双目、双目深度已经用在什么位置、为什么鱼眼图像需要校正，以及 MediaPipe 与 MANO 各自负责什么。

## 结论先行

1. 当前实时系统不是纯单目。MediaPipe 本身是单图输入，因此程序在左、右相机上各运行一次；随后进行跨相机关联、21点三角化、深度质量过滤和 MANO 拟合。界面只显示原始左鱼眼画面，是显示方式造成的“看起来像单目”。
2. 当前已经使用双目深度，但属于“21个手部关节点的稀疏深度”，不是整幅图的稠密深度图，也不是相机提供的独立硬件深度流。
3. 对当前 KB/Kannala–Brandt 鱼眼双目，三角化前必须处理畸变并统一到同一个双目校正坐标系。不能把原始鱼眼图上的 MediaPipe 归一化坐标直接交给校正后的 `P1/P2` 三角化。
4. MediaPipe 单独检测并没有接口层面的“必须先去畸变”要求；但本设备视场宽、边缘形变强，在校正图上检测通常能获得更一致的手指几何。这是针对本设备的工程判断，而不是 MediaPipe 官方保证。
5. MANO 不负责检测手，也不产生相机深度。它是低维参数化手部网格模型，必须由双目3D、左右2D重投影、时序和先验共同约束。
6. 下一步不应从零“再加一次深度”，而应提高左右21点对应精度：在校正图的水平极线上做局部匹配/亚像素优化，再进行置信度融合。它比直接上全画面稠密双目更适合当前实时性能目标。

```text
             +------+------+
             |             |

       MediaPipe       MediaPipe

             |             |
             +------+------+
                    v
       极线、视差、handedness 软约束关联
                    |

      P1/P2 三角化 -> 左相机光学坐标系米制3D
                    |
                    v

                    |

                    |

  使用原始左相机 K、D 将网格投回原始鱼眼画面显示
```

实时主循环已经明确执行：

- 对左右图分别调用 `cv2.remap`；
- 创建两个 Hand Landmarker，并行检测左右校正图；
- 对左右手实例执行 `associate_hands`；
- 使用 `cv2.triangulatePoints(P1, P2, ...)`；
- 将过滤后的 `filtered_points_left` 送入 MANO；
- MANO 损失同时包含左、右两幅校正图的2D重投影项。

因此，主界面只显示左目不等于算法只使用左目。运行以下命令可直接查看左右校正图的双目诊断模式：

```bash

conda activate ego-hand
unset PYTHONPATH
scripts/run_ego_live.sh --no-mano
```

## 三种“3D/深度”不能混淆

### 1. MediaPipe 图像 landmarks 的 z

MediaPipe 的图像 landmark 中，`x/y` 是图像归一化坐标，`z` 是以手腕附近为参考的模型相对深度，量级与归一化 `x` 接近。它不是左相机坐标系中的米制深度。

### 2. MediaPipe world landmarks

官方文档将 world landmarks 定义为以手部近似几何中心为原点、单位为米的手部模型坐标。因为原点绑定在手本身，而不是相机光心，所以它可描述相对手形，但不能给出手距相机多少米，也不能替代双目三角化。

### 3. 本项目的双目3D

本项目用同步左右校正像素和 `P1/P2` 三角化，再转换到原始左相机光学坐标系，输出：

```text
x_left_camera_m
y_left_camera_m
z_left_camera_m
```

这才是当前跟踪、空间位置和 MANO 平移应使用的相机米制3D。

## 为什么当前双目必须校正

这里要区分两个概念：

- 去畸变：补偿单个镜头的鱼眼畸变；
- 双目校正：在去畸变基础上，根据左右外参旋转两幅图，使对应点落在同一条水平极线上，并生成新的 `P1/P2`。

OpenCV 的鱼眼接口中，`fisheye.stereoRectify` 根据 `K1/D1/K2/D2/R/T` 生成 `R1/R2/P1/P2/Q`；`fisheye.initUndistortRectifyMap` 再生成供 `remap` 使用的图像映射。使用这些 `P1/P2` 调用 `triangulatePoints` 时，输入点必须属于相应的校正图坐标系，输出位于第一相机的校正坐标系。

如果将原始鱼眼像素直接与校正后的 `P1/P2` 混用，会破坏以下假设：

- 左右对应点具有相同或接近的 y；
- 视差主要出现在 x 方向；
- 投影矩阵与输入像素属于同一个成像模型；
- 重投影误差具有可比较的像素意义。

结果通常是深度跳变、指尖飞点、左右手错误关联和 MANO 网格漂移。

### MediaPipe 是否必须检测校正图

严格地说，MediaPipe 可以接收任意普通 RGB 图像，并不要求调用者提供相机内参或畸变系数。因此“仅仅得到2D landmarks”时，程序可以直接检测原始鱼眼图。

但是 EGO 使用强鱼眼镜头，手靠近边缘时手指长度、角度和掌形会发生明显非线性拉伸。MediaPipe 的模型并不会显式利用本机 KB 标定恢复真实射线。基于这一点，本项目选择先校正、再检测，目的是：

- 让左右相机中的同一关节更接近相同的针孔投影几何；
- 让极线距离和视差门限有明确意义；
- 降低画面边缘形变对左右独立预测的一致性影响；
- 让检测像素可直接用于 `P1/P2` 三角化。

代价是校正参数 `balance` 会影响视场与有效像素密度。`balance=0` 通常畸变较小、裁剪更多；提高 balance 可保留更多边缘视场，但会牺牲中心有效分辨率或引入黑边。应通过真实手部覆盖范围和极线误差选择，而不是只看画面是否“宽”。

## MANO 阶段如何处理畸变

MANO 本身只生成局部3D关节和网格，不读取鱼眼图，也不知道镜头畸变。畸变由“如何把 MANO 3D 投影到图像”决定。

当前做法是正确的两坐标路径：

1. 优化时，将 MANO 关节投到左右校正平面，与 MediaPipe 校正像素比较；
2. 最终显示时，使用左相机原始 `K/D` 和 `cv2.fisheye.projectPoints` 投回原始鱼眼图。

实时优化的核心形式可概括为：

```text
L = L_stereo_3D
  + lambda_2D * (L_left_rectified + L_right_rectified)
  + lambda_pose * L_pose_prior
  + lambda_time * L_temporal
```

这保证“计算使用校正几何，显示保留原始大视场”。不能直接用普通针孔 `projectPoints` 把网格画回原始鱼眼图，也不能将原始鱼眼2D点与校正投影混在同一个损失中。

## 双目深度能改善什么

双目深度对当前项目有实际价值：

- 给出相机坐标系下的真实尺度、位置和平移；
- 双手在2D交叉但 Z 不同时，降低轨迹ID互换；
- 使用极线误差、视差和重投影误差拒绝错误关节点；
- 为 MANO 的掌部朝向、大小和空间位置提供强约束；
- 单目短时遮挡时，可利用历史三维速度做有限预测。

但双目不会自动解决全部问题。当前左右 MediaPipe 是两次独立神经网络预测，同一个语义关节可能存在1至数像素的偏差。根据近似关系：

```text
Z ≈ f * B / disparity
```

当视差较小或像素对应误差较大时，Z误差会被放大。指尖、快速运动、两手互相遮挡、运动模糊和鱼眼边缘区域仍然最不稳定。

## 是否应该增加稠密深度

可以研究，但不建议把“整幅稠密双目”作为当前第一优先级。

当前程序没有读取独立硬件 depth stream，深度来自左右彩色图。若增加 StereoBM/SGBM 或深度网络，可尝试：

- 用掌面附近的可靠深度辅助整体平移和手掌法向；
- 为 MANO 增加网格表面到深度图的鲁棒损失；
- 在遮挡边界帮助判断前后手。

风险包括：

- 皮肤和衣物常为低纹理区域，稠密匹配不一定可靠；
- 手指细、遮挡多，左右可见区域不同；
- 全分辨率 1600×1300 双路计算会显著增加实时延迟；
- USB2 输入带宽和 MediaPipe CPU 推理目前已经是明显瓶颈；
- 错误稠密深度如果权重过大，会把 MANO 拉到错误表面。

更合适的顺序是先提高21点的稀疏对应质量，再决定是否增加掌部局部稠密深度。

## 优化阶段状态

### P0：先验证标定和实时输入

- 尽量使用直连 USB3，避免输入帧对不足造成观感卡顿；
- 用标定板重新统计校正后的垂直极线误差；
- 检查左右时间戳差、丢帧和运动模糊；
- 确认设备 Flash 标定与当前分辨率完全一致。

### P1：关节点极线亚像素优化（已实现第一版）

保留 MediaPipe 的语义识别，但不直接把左右独立预测像素当作最终对应点：

1. 以左/右 MediaPipe 预测作为初值；
2. 只在校正图相同 y 附近的小窗口搜索；
3. 使用局部纹理、梯度或特征相关性修正 x；
4. 进行左右一致性检查和亚像素拟合；
5. 再计算视差、深度和重投影误差。

这一步直接针对当前指尖深度抖动的主要来源，计算量也远小于全图稠密深度。

当前实现位于 `scripts/mediapipe_stereo_triangulate.py`，由实时和离线双目程序
共同调用。它使用校正图稀疏LK、前后向一致性、水平极线残差和指尖大窗口；
失败时保留原MediaPipe点并降低质量权重。参数和初步验证结果见
[`EGO_REALTIME.md`](EGO_REALTIME.md)。

### P2：不确定度感知融合

- 检测置信度低、极线误差大或重投影误差大的点降低权重；
- 掌根/MCP承担更多刚体定位权重，指尖保持更强时序和骨长约束；
- 观测与预测必须保留不同状态，不将长时缺失伪装成真实关节；
- MANO 的2D和3D损失按每个关节的深度质量动态加权。

### P3：实时计算异步化

- 采集、解码、MediaPipe、三角化和 MANO 分阶段有界队列；
- MediaPipe/三角化按最新帧运行，MANO允许较低频更新并用上一状态渲染；
- 显示线程不阻塞采集；
- 保留阶段耗时统计，区分 USB、解码、检测、MANO 和渲染瓶颈。

### P4：可选的局部深度图

仅在 P1/P2 稳定后，对手部 ROI 计算局部双目深度，并只把通过左右一致性、纹理和时间一致性检查的深度用于掌面约束。

## 验收指标

不要只看“网格像不像”，建议同时保存：

- 左右帧设备时间戳差；
- 校正后同名关节的垂直极线误差；
- 左右重投影误差；
- 每关节有效3D率，尤其5个指尖；
- 深度速度/加速度异常次数；
- 遮挡前后 `track_id` 是否保持；
- MANO 左右2D误差和3D关节误差；
- 各阶段耗时、端到端延迟和主动丢帧数。

建议同时运行两个视图：

```bash
# 双目几何诊断：必须能看到左右校正图和对应骨架
scripts/run_ego_live.sh --no-mano --record

# 完整效果：原始左鱼眼 + MANO + 21-DOF
scripts/run_ego_live.sh --record
```

## 最终判断

当前架构方向是正确的：左右鱼眼先双目校正，各自进行 MediaPipe 语义检测，再用双目几何得到相机坐标系深度，最后用双目3D和双目2D共同约束 MANO。需要优化的是左右关节点的精确对应、质量加权和实时流水线，而不是退回单目，也不是简单叠加一个未经验证的稠密深度结果。
